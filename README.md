# StudyBot

Личный бот. Собирает учебные задания из Telegram и из СДО МИРЭА и каждый вечер в 20:00 МСК присылает сводку: просрочено / сегодня / завтра / на неделе / без срока. Под сводкой кнопки «✅ N», чтобы отметить задание выполненным.

**Бот не входит в твой аккаунт Telegram.** Это обычный бот через Bot API, и сообщения к нему попадают двумя путями:
- **ты пересылаешь ему сообщение** из группы или пишешь текст сам — бот достаёт оттуда задания. Дата пересланного сообщения берётся из оригинала, так что «к пятнице» считается правильно;
- **бота добавили в учебную группу** (это делает админ или староста) — тогда он читает её сам. Работает только для групп из `CHAT_IDS`.

```
пересылка / группа ─► фильтр ─► правила (или Claude) ─┐
                                                      ├─► SQLite ─► 20:00 ─► бот ─► ты
СДО МИРЭА (раз в 30 мин) ─────────────────────────────┘
```

### Разбор сообщений: бесплатно правилами
По умолчанию LLM не используется ([study_bot/extract/rules.py](study_bot/extract/rules.py)). Бот понимает такие сроки:
- `до 25.10`, `25.10.2026`, `25 октября`;
- `к пятнице`, `в пт`, `к следующей среде`;
- `сегодня`, `завтра`, `послезавтра`, `через 3 дня`, `через неделю`;
- время вида `в 10:30`.

Если в сообщении «перенесли с пятницы на вторник», берётся последний срок. Нумерацию вроде «лаба 2.1» бот за дату не считает. Сообщение со списком «1. … 2. …» превращается в отдельные задания, а срок из заголовка («ДЗ до пятницы:») достаётся пунктам без своего срока.

Предмет бот определяет по названиям курсов с портала («по фронтенду» → «Фронтенд и бэкенд разработка») и по сокращениям: встроенным («матан», «линал», «англ») и твоим из `SUBJECT_ALIASES`.

Если бот что-то не распознал, добавь задание вручную: `/add …`. Если указать `ANTHROPIC_API_KEY`, вместо правил разбирать будет Claude. Это точнее на запутанных формулировках, но платно.

## Запуск

1. Подготовь ключи:
   - `cp .env.example .env`
   - `BOT_TOKEN` выдаёт @BotFather.
   - `OWNER_ID` — твой id, его покажет @userinfobot.
   - `ANTHROPIC_API_KEY` — не обязателен (без него разбор бесплатный, правилами).
2. Запусти бота:
   ```bash
   uv run python -m study_bot.main
   ```
3. Напиши боту `/start`, затем пришли `/cookie …` для портала (раздел ниже).

### Команды бота
- пересланное сообщение или любой текст — разобрать задания;
- `/digest` — сводка сейчас;
- `/tasks` — все открытые задания, включая дальние;
- `/add до 30.10 реферат по истории` — добавить как есть, даже если LLM не нашла задание;
- `/cookie <MoodleSession>` — подключить или обновить сессию портала.

### Если бота добавят в группу
1. В @BotFather: `/setprivacy` → выбери бота → **Disable**. Без этого бот в группе видит только команды. Если сделать бота админом, privacy mode можно не трогать.
2. Когда бота добавят, он пришлёт тебе id группы. Впиши его в `.env` как `CHAT_IDS=[-100…]` и перезапусти бота.
3. Сообщения, отправленные до добавления, бот не видит. Важное из прошлого можно просто переслать ему.

## Mini App

Приложение открывается внутри Telegram: кнопкой «Задания» слева от поля ввода, кнопкой «📋 Открыть приложение» под сводкой или «✏️ Открыть» под уведомлением о новом задании (сразу в карточку).

- список по секциям (просрочено / сегодня / завтра / на неделе / позже / без срока / сделано), фильтр по предмету, сумма баллов на неделю;
- карточка: текст, предмет, срок и время, баллы, ссылка; удалить; статус в СДО (черновик, ждёт оценки, оценено N из M, попытки теста);
- задания СДО, исправленные вручную, больше не перезаписываются порталом; удалённое из СДО прячется и не возвращается.

Код: API — [study_bot/webapp.py](study_bot/webapp.py) (в том же процессе, что бот), фронтенд — [study_bot/webapp_static/](study_bot/webapp_static/).
Вход — подписанные Telegram данные (`initData`), проверяются токеном бота; пускает только `OWNER_ID`.

**Локально посмотреть в браузере:** `WEBAPP_DEV_NO_AUTH=true` в `.env`, запустить бота, открыть http://127.0.0.1:8080. Этот флаг выключает проверку — только на своём компьютере, никогда на сервере.

**В Telegram** приложение откроется только по https: нужен `WEBAPP_URL` (VPS + домен, см. ниже). Кнопку меню бот ставит сам при запуске.

## VPS

```bash
rsync -av --exclude .venv ./ vps:~/studybot/
ssh vps 'cd ~/studybot && docker compose up -d --build && docker compose logs -f'
```
`.env` и `data/` (база и cookie портала) в git не попадают — перенеси `.env` на сервер руками, cookie пришли боту командой `/cookie` уже там.

## Портал (СДО МИРЭА)

`online-edu.mirea.ru` работает на Moodle. Мобильный веб-сервис для SSO-входа там отключён. Поэтому бот ходит тем же путём, что и сама страница: берёт cookie `MoodleSession`, достаёт `sesskey` со страницы `/my/` и вызывает AJAX-метод `core_calendar_get_action_events_by_timesort`. Ответ содержит задания и тесты, которые ещё нужно сдать. Когда задание сдано, оно пропадает из ответа, и бот сам отмечает его выполненным.

Как подключить:
1. Войди на online-edu.mirea.ru в обычном браузере.
2. Открой DevTools → Application → Cookies → `online-edu.mirea.ru` и скопируй значение `MoodleSession`.
3. Пришли боту `/cookie <значение>`. Бот сразу удалит это сообщение и проверит доступ.

Бот опрашивает портал раз в 30 минут, и это не даёт сессии истечь. Если она всё же протухнет (сменил пароль, вышел на всех устройствах), бот один раз пришлёт инструкцию, как обновить cookie. Значение хранится в `data/moodle_session.txt` с правами 600 и в git не попадает.

> Пока активна сессия бота, не нажимай «Выйти» на портале: выход убивает именно эту сессию. Если просто закрыть вкладку, сессия останется.

Проверить, что портал отдаёт задания:
```bash
uv run python -m study_bot.sources.portal
```
