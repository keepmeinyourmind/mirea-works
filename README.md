# StudyBot

Закрытый Telegram-бот для учёбы на нескольких человек (@mireahometaskbot). Он собирает задания из СДО МИРЭА и из сообщений, которые ему пересылают, и каждый вечер присылает сводку: просрочено / сегодня / завтра / на неделе / дальше / без срока. Под сводкой есть кнопки «✅ N», чтобы отметить задание выполненным, и кнопка Mini App со списком и карточками заданий.

Бот круглосуточно работает на VPS (раздел [Сервер](#сервер)), поэтому Mac для него включать не нужно.

**Бот не входит в твой аккаунт Telegram.** Это обычный бот через Bot API, и сообщения к нему попадают двумя путями:
- **пользователь пересылает ему сообщение** из группы или пишет текст сам — бот достаёт оттуда задания. Дата пересланного сообщения берётся из оригинала, так что «к пятнице» считается правильно;
- **бота добавили в учебную группу** — тогда он читает её сам. Работает только для групп из `CHAT_IDS`, и задания оттуда получает только админ.

```
пересылка / группа ─► фильтр ─► правила (или Claude) ─┐
                                                      ├─► SQLite ─► сводка в своё время ─► бот / Mini App
СДО МИРЭА (раз в 30 мин, у каждого своя cookie) ──────┘
```

## Команды бота

Для всех:
- пересланное сообщение или любой текст — разобрать задания;
- `/digest` — сводка сейчас;
- `/tasks` — все открытые задания, включая дальние;
- `/add до 30.10 реферат по истории` — добавить задание как есть, даже если разбор его не нашёл;
- `/cookie <MoodleSession>` — подключить или обновить СДО ([как взять cookie](#портал-сдо-мирэа));
- `/time 21:00` — время своей сводки (по умолчанию 20:00 МСК);
- `/forget` — удалить все свои данные;
- `/help` — справка.

Только для админа (`OWNER_ID`):
- `/invite` — одноразовая ссылка-приглашение;
- `/users` — кто пользуется, подключено ли СДО, сколько заданий;
- `/kick <id>` — отключить человека и удалить его данные;
- `/status` — загрузка сервера (процессор, память, диск) и состояние бота (пользователи, истёкшие сессии СДО, размер базы).

## Напоминания

Кроме вечерней сводки бот сам пишет:
- **⏳ за сутки до срока** — ночью (с 23 до 8) не будит, такое напоминание придёт утром;
- **⏰ за 3 часа до срока** — приходит всегда, даже ночью;
- **⚠️ про черновик в СДО**: файл загружен, но не отправлен на проверку, а до срока меньше суток.

Каждое напоминание приходит один раз. Если срок перенесли, бот напомнит заново. Если задание появилось, когда до срока уже меньше суток (сам добавил, бот только что нашёл его в СДО), напоминания «за сутки» не будет: о новом задании и так только что пришло сообщение. Под напоминанием есть кнопки «✅ N». Настройки в `.env`: `REMINDERS`, `REMIND_DAY_HOURS`, `REMIND_SOON_HOURS`, `QUIET_FROM_HOUR`, `QUIET_TO_HOUR`.

## Пользователи

Бот закрытый: им пользуются админ и те, кого он пригласил. Остальным бот отвечает, что он закрыт.

**Как работает приглашение.** `/invite` создаёт случайный одноразовый код и ссылку `https://t.me/mireahometaskbot?start=КОД`. Когда человек открывает ссылку и нажимает «Запустить», Telegram присылает боту `/start КОД` вместе с id этого человека, и подделать id нельзя. Бот гасит код и добавляет человека, а админу приходит сообщение «подключился по приглашению». Новичку бот показывает, какие данные он хранит, и объясняет, как подключить СДО.

У каждого своё: задания из СДО (по своей cookie), пересланные сообщения, отметки и правки, время сводки. В Mini App человек видит только свои задания: его id берётся из подписанных Telegram данных.

Cookie СДО хранятся в базе в зашифрованном виде (Fernet). Ключ — `COOKIE_KEY` в `.env`, в базе его нет. **Не теряй и не меняй `COOKIE_KEY`**: без него сохранённые cookie не расшифровать, и всем придётся заново прислать `/cookie`.

## Разбор сообщений: бесплатно правилами

По умолчанию LLM не используется ([study_bot/extract/rules.py](study_bot/extract/rules.py)). Бот понимает такие сроки:
- `до 25.10`, `25.10.2026`, `25 октября`;
- `к пятнице`, `в пт`, `к следующей среде`;
- `сегодня`, `завтра`, `послезавтра`, `через 3 дня`, `через неделю`;
- время вида `в 10:30`.

Если в сообщении «перенесли с пятницы на вторник», берётся последний срок. Нумерацию вроде «лаба 2.1» бот за дату не считает. Сообщение со списком «1. … 2. …» превращается в отдельные задания, а срок из заголовка («ДЗ до пятницы:») достаётся пунктам без своего срока.

Предмет бот определяет по названиям курсов с портала («по фронтенду» → «Фронтенд и бэкенд разработка») и по сокращениям: встроенным («матан», «линал», «англ») и заданным в `SUBJECT_ALIASES`.

Если бот что-то не распознал, задание можно добавить вручную: `/add …`. Если указать `ANTHROPIC_API_KEY`, вместо правил разбирать будет Claude (на сервере запросы к нему идут через туннель). Это точнее на запутанных формулировках, но платно.

## Mini App

Приложение открывается внутри Telegram: кнопкой «Задания» слева от поля ввода, кнопкой «📋 Открыть приложение» под сводкой или «✏️ Открыть» под уведомлением о новом задании (сразу в карточку). Адрес — https://mirea-hometask.duckdns.org.

- главный экран: полоска недели (тап по дню — задания только этого дня), карточка «Ближайший дедлайн» с обратным отсчётом, просроченное отдельными плашками, дальше задания по дням, «позже», «без срока», «готово»; фильтр по предмету, кольцо «сделано за неделю», сумма баллов на неделю;
- оформление (кнопка с палитрой): цвета «Индиго», «Мята», «Закат», «Океан», «Графит» и тема «Авто / Светлая / Тёмная». Выбор хранится в Telegram (CloudStorage) и одинаков на всех устройствах;
- карточка: текст, предмет, срок и время, баллы, ссылка; удалить; статус в СДО (черновик, ждёт оценки, оценено N из M, попытки теста);
- задания СДО, исправленные вручную, больше не перезаписываются порталом; удалённое из СДО прячется и не возвращается.

Код: API — [study_bot/webapp.py](study_bot/webapp.py) (в том же процессе, что бот), фронтенд — [study_bot/webapp_static/](study_bot/webapp_static/).
Вход — подписанные Telegram данные (`initData`), которые проверяются токеном бота. Пускают только пользователей бота (админа и приглашённых), каждый видит только свои задания.

## Сервер

VPS в Москве: Ubuntu 24.04, 1 vCPU, 1 ГБ RAM, `ssh studybot` (вход по ключу `~/.ssh/studybot`). Домен `mirea-hometask.duckdns.org` указывает на сервер. Проект лежит в `/root/studybot`, внутри три контейнера ([docker-compose.yml](docker-compose.yml)):
- **bot** — бот, планировщик и API приложения. База и бэкапы — в `/root/studybot/data`;
- **xray** — клиент VLESS. Из российского дата-центра Telegram и Claude напрямую недоступны, поэтому бот ходит к ним через туннель (`TELEGRAM_PROXY`, `HTTPS_PROXY`). СДО открывается напрямую;
- **caddy** — https ([deploy/Caddyfile](deploy/Caddyfile)): сам получает и продлевает сертификат Let's Encrypt.

Наружу открыты только порты 22, 80 и 443 (ufw). Конфиг Xray собран из ссылки VLESS прямо на сервере (`/root/xray`), в git его нет. `WEBAPP_DEV_NO_AUTH` на сервере всегда выключен, и с ним на не-локальном адресе бот не запустится.

**Защита сервера:**
- **SSH только по ключу:** вход по паролю выключен (`/etc/ssh/sshd_config.d/00-studybot.conf`). Потеряешь ключ `~/.ssh/studybot` — войти можно будет только через консоль VNC в панели хостинга.
- **fail2ban:** 5 неудачных попыток входа за 10 минут — бан IP на сутки (`/etc/fail2ban/jail.local`). Кого забанил: `ssh studybot fail2ban-client status sshd`.
- **Логи Docker** ограничены: не больше 3 файлов по 10 МБ на контейнер, диск ими не забьётся.

**Обновить бота** после изменений в коде (с Mac):
```bash
scripts/deploy.sh
```
Скрипт прогонит тесты, скопирует код и `.env` на сервер, сохранит копию базы (5 последних, `data/tasks.backup-*.sqlite3`) и пересоберёт контейнеры.

**Логи:**
```bash
ssh studybot 'cd /root/studybot && docker compose --env-file deploy.env logs -f bot'
```

**Перезапустить** (без пересборки):
```bash
ssh studybot 'cd /root/studybot && docker compose --env-file deploy.env restart bot'
```

**Загрузку сервера** проще всего посмотреть командой `/status` в боте.

> Одновременно может работать только один бот с этим токеном. Если запускаешь бота на Mac (для разработки), сначала останови его на сервере: `docker compose … stop bot`, а потом снова запусти через `scripts/deploy.sh`.

## Портал (СДО МИРЭА)

`online-edu.mirea.ru` работает на Moodle. Мобильный веб-сервис для SSO-входа там отключён. Поэтому бот ходит тем же путём, что и сама страница: берёт cookie `MoodleSession`, достаёт `sesskey` со страницы `/my/` и вызывает AJAX-метод `core_calendar_get_action_events_by_timesort`. Ответ содержит задания и тесты, которые ещё нужно сдать. Когда задание сдано, оно пропадает из ответа, и бот сам отмечает его выполненным. Баллы и статусы (черновик, оценено, попытки) бот берёт со страниц самих заданий и тестов.

Как подключить (каждый делает сам):
1. Войди на online-edu.mirea.ru в приватном окне браузера.
2. Открой DevTools → Application (в Safari — Хранилище) → Cookies → `online-edu.mirea.ru` и скопируй значение `MoodleSession`.
3. Пришли боту `/cookie <значение>`. Бот сразу удалит это сообщение, зашифрует cookie и проверит доступ.
4. Закрой приватное окно, **не нажимая «Выйти»**: выход убивает именно эту сессию.

Бот опрашивает портал раз в 30 минут (пользователей по очереди), и это не даёт сессиям истечь. Если сессия всё же протухнет (сменил пароль, вышел на всех устройствах), бот один раз пришлёт этому человеку инструкцию, как обновить cookie.

## Разработка

```bash
uv run pytest
```

### Локальный запуск

1. Подготовь `.env`:
   - `cp .env.example .env`
   - `BOT_TOKEN` выдаёт @BotFather.
   - `OWNER_ID` — твой id, его покажет @userinfobot.
   - `COOKIE_KEY` — ключ шифрования cookie (команда в `.env.example`). Для сервера используется тот же `.env`, его копирует `scripts/deploy.sh`.
   - `ANTHROPIC_API_KEY` — не обязателен (без него разбор бесплатный, правилами).
2. Останови бота на сервере (см. выше) и запусти локально:
   ```bash
   uv run python -m study_bot.main
   ```

**Mini App в браузере:** `WEBAPP_DEV_NO_AUTH=true` в `.env`, запустить бота, открыть http://127.0.0.1:8080. Этот флаг выключает проверку Telegram — только на своём компьютере, никогда на сервере. В самом Telegram приложение открывается только по https, то есть с сервера.

### Автозапуск на Mac (запасной вариант)

До переезда на сервер бот работал на Mac через launchd. Сейчас он там выключен. Если сервер когда-нибудь будет недоступен:
```bash
scripts/autostart.sh install     # поставить и запустить
scripts/autostart.sh status      # работает ли
scripts/autostart.sh logs        # последние строки лога (data/bot.log)
scripts/autostart.sh uninstall   # убрать
```
Пока бот работает, Mac не засыпает от бездействия (`caffeinate -i`), но закрытая крышка всё равно его усыпляет. После пробуждения бот догонит пропущенную сводку (не позже чем через `DIGEST_GRACE_HOURS`, по умолчанию 6 ч). Учти, что база на Mac и на сервере разная.

### Если бота добавят в группу
1. В @BotFather: `/setprivacy` → выбери бота → **Disable**. Без этого бот в группе видит только команды. Если сделать бота админом, privacy mode можно не трогать.
2. Когда бота добавят, он пришлёт админу id группы. Впиши его в `.env` как `CHAT_IDS=[-100…]` и выполни `scripts/deploy.sh`.
3. Сообщения, отправленные до добавления, бот не видит. Важное из прошлого можно просто переслать ему.
